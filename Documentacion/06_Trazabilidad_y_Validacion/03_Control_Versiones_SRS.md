# 03. Control de Versiones del SRS
## Sistema de Gestión para Refugio de Animales de Compañía (SG-RAC)

### 1. Propósito
Mantener un registro ordenado de las versiones del SRS, sus modificaciones, responsables y aprobaciones, de manera que el equipo pueda identificar cuál es la versión vigente y justificar cada cambio.

### 2. Identificación del documento
- **Documento:** Especificación de Requerimientos de Software (SRS).
- **Sistema:** Sistema de Gestión para Refugio de Animales de Compañía (SG-RAC).
- **Institución:** Escuela Politécnica Nacional.
- **Asignatura:** Diseño y Programación de Software.
- **Integrantes indicados en el SRS fuente:** Jeff Limones, Ángel Urrea y Erika.
- **Versión de este consolidado:** 1.0 (borrador de consolidación).
- **Estado:** Pendiente de revisión y aprobación.

### 3. Historial de cambios

| Versión | Fecha | Descripción del cambio | Responsable | Estado |

| 1.0 | 26-11-2026 | Consolidación documental de los requerimientos y artefactos PPE07/PPE08 a partir del SRS entregado | Equipo del proyecto | Borrador, pendiente de aprobación |

**Importante:** La fecha y versión anteriores identifican este documento consolidado. No representan una aprobación formal ni sustituyen el historial real de cambios del repositorio. El equipo debe completar las futuras entradas con cada modificación efectivamente realizada.

### 4. Procedimiento de control de cambios
1. Registrar la solicitud de cambio e identificar el requerimiento afectado.
2. Describir el motivo y el impacto sobre casos de uso, historias, pruebas y otros documentos.
3. Revisar el cambio con el equipo y el Administrador del refugio cuando corresponda.
4. Aprobar o rechazar la solicitud y registrar quién tomó la decisión.
5. Actualizar el SRS y los artefactos relacionados.
6. Incrementar la versión y registrar el cambio en esta tabla.
7. Conservar la versión anterior en el historial de Git.

### 7. Convención recomendada para Git
- Utilizar mensajes descriptivos, por ejemplo: `docs: agrega matriz de trazabilidad`.
- Mantener los documentos en las carpetas definidas para PPE07 y PPE08.
- No sobrescribir cambios aprobados sin registrar la nueva versión.
- Utilizar etiquetas de Git para identificar versiones formales del SRS, una vez aprobadas.

### 8. Estado final
